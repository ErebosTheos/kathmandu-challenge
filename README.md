# Rokne Thau · Koteshwor Chowk

A browser traffic simulator for Koteshwor Chowk in Kathmandu. Compare the modeled junction, short-term surface changes, and a long-term tunnel and skybridges under the same traffic demand.

## How to use the site

1. Select **Open the simulator** and choose a traffic condition. Start with **Morning rush**, or choose **Bus bunching**, **Evening peak + rain**, **Dashain exodus**, or **Sandbox**.
2. Select **Run**. All three plans run on the same seeded demand. Use the plan buttons or keys **1–3** to switch views. On a phone, tap **Plans** to show the plan buttons.
3. Compare **Now** (the modeled baseline), **Short-term** (surface changes to signals, lanes, boarding, and crossings), and **Long-term** (a tunnel and skybridges with adaptive signals and bus bays). In Long-term, toggle **Tunnel cutaway** to see through traffic below the junction.
4. Select **Results** after the run starts. The comparison pauses at the elapsed time and shows total person-delay, people through, boarding lane blockage, and modeled unsafe crossings. Lower delay and fewer unsafe crossings are separate outcomes. Select **Back to simulation** to return to the paused run.
5. Open **Plan guide** from Home, the simulator, or Results for a breakdown of each measure and the benchmark across traffic conditions. The benchmark averages five 10-minute runs. Open **Valley audit** from Home to explore mapped bus stops near signals and major junctions.

### Controls

- **Camera** · Drag to orbit, right-drag to pan, and scroll to zoom. On touch, drag to orbit and use two fingers to zoom or pan. Choose **Overview**, **Street**, or **Bird** for a preset view.
- **Vehicle details** · Select a surface vehicle to view its plate, route, and delay. Then select **Follow** to track it.
- **Playback** · Press **Space** to pause or resume, or use the speed buttons to advance at up to **8×**.
- **Live comparisons** · Turn on **Heatmap** for queues, **Now (inset)** for a baseline view, or **Charts** for delay over time.

Read the [project and plan guide (PDF)](output/pdf/Koteshwor%20Traffic%20Challenge%20-%20Project%20and%20Plan%20Guide.pdf) for why we chose Koteshwor, the Kathmandu Valley context, and the full benchmark tables.

## Run locally

From the project folder, install the dependencies and start the development server.

```sh
npm install
npm run dev
```

Open the local URL Vite prints in a browser with WebGL 2 enabled. For a production build, run `npm run build` and then `npm run preview`, or serve the generated `dist/` folder over HTTP.

## Tests

Run `npm test` for the simulation tests. To check the site in a browser, install Playwright Chromium once with `npx playwright install chromium`, keep the local server running, and run `npm run test:browser`. It defaults to `http://127.0.0.1:5173/`. Set `DEMO_URL` for a different server. Screenshots go to `logs/shots/`.

## Data and credits

OpenStreetMap contributors provide the junction and Valley geometry under the [ODbL](https://www.openstreetmap.org/copyright). The checked-in audit is generated by `npm run audit` from the two Valley Overpass extracts in `data/raw/`. It uses straight-line metres to the closest mapped signal or major-road junction. Junction candidates have at least three connections in the mapped trunk, primary and secondary network. The ranking is a proximity screen.

The live scene uses the repo's Blender GLB exports and works without still renders. Procedural frontage and background buildings are illustrative. The in-game model notes document assumed demand, compliance, operating costs, pedestrian behaviour and plate conventions. Photo references and individual credits are in [references/README.md](references/README.md).
